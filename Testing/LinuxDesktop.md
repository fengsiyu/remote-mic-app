# Linux 桌面版测试手册

## 适用范围

- 目标版本：`sayall-linux 0.1.0` 候选。
- 目标系统：Ubuntu 20.04 及以上、`amd64`；PulseAudio 或带 Pulse 兼容 `pactl` 的 PipeWire。
- 目标硬件：小米蓝牙遥控器 2 / 2 Pro，以及名称或 Vendor/Product `0x2717:0x32B8` 匹配的 RC001/RC003 兼容设备。
- 本文只定义验证方法和通过证据，不新增产品行为；产品规则见 [`feature/linux-desktop/PRODUCT_SPEC.md`](../feature/linux-desktop/PRODUCT_SPEC.md)。

## 测试前准备

1. 使用 Ubuntu 20.04+ `amd64` 实机，确认系统时间、蓝牙服务和音频服务正常。
2. 安装测试包：`sudo apt install ./sayall-linux_0.1.0_amd64.deb`。
3. 重新登录，使 udev `uaccess` 和用户组规则生效；必要时执行 `sudo modprobe uinput`。
4. 在系统蓝牙设置中配对并连接遥控器。
5. 在目标语音工具中选择麦克风 `SayAll`，并把按住说话快捷键设为 `F5`，或与应用中配置的触发键一致。
6. 只启动一个 `sayall-linux` 实例。

## 自动化与构建检查

在仓库根目录执行：

```bash
PYTHONPATH=linux python3 -m unittest discover -s linux/tests -t linux -v
python3 -m compileall -q linux/sayall_linux linux/tests
bash -n linux/packaging/build-deb.sh
desktop-file-validate linux/packaging/sayall-linux.desktop linux/packaging/sayall-linux-autostart.desktop
bash linux/packaging/build-deb.sh
dpkg-deb --info dist/sayall-linux_0.1.0_amd64.deb
```

通过标准：31 项单元测试全部通过；编译和脚本语法检查无错误；桌面入口无 error；`.deb` 可构建并能通过 `--version` 加载。

## 实机用例

### 1. 安装、启动与卸载边界

步骤：

1. 安装 `.deb`。
2. 从应用菜单启动 `SayAll`。
3. 退出后执行 `sayall-linux --version`。
4. 注销并重新登录，观察是否自动启动。
5. 执行 `sudo apt remove sayall-linux`，确认用户配置默认保留。

预期：

- 应用菜单出现“SayAll / 无线麦 SayAll”。
- 主窗口可显示；存在状态栏扩展时，`--minimized` 可隐藏主窗口。
- `--version` 输出 `SayAll 0.1.0`。
- 登录后自动启动，且不会重复创建两个音频模块或两个 uinput 设备。

失败判定：安装后无入口、启动即崩溃、重复初始化、卸载删除用户配置或输出版本不正确。

### 2. 蓝牙发现、配对与连接

步骤：

1. 关闭遥控器后重新打开，观察应用页面。
2. 在应用中选择遥控器并等待连接。
3. 断开系统蓝牙，再重新连接。
4. 将遥控器移出范围，等待断连，再移回范围。

预期：

- 设备名称出现在列表中，状态依次显示扫描、连接和语音链路准备。
- 连接后订阅 Audio/Control 通知并读取能力；语音状态变为就绪。
- 断连后显示未连接；恢复范围后可重新连接，旧语音会话不得残留。

失败判定：只能第二次连接、连接后无 GATT 就绪、断连后永久卡在收音、错误匹配无关蓝牙设备。

### 3. 虚拟麦克风准备

步骤：

1. 打开应用页面，记录虚拟麦克风状态。
2. 执行 `pactl list short sources`，查找 `SayAll`。
3. 点击“重新准备麦克风”。
4. 在目标语音工具中查看输入设备列表。

预期：

- `SayAll` 音源出现，格式为 16 kHz、单声道、`s16le`。
- 目标语音工具可选择 `SayAll`。
- 重启准备成功后旧模块被清理，不出现多个同名音源。
- 语音会话进行中点击重启必须被拒绝并显示原因。

失败判定：没有 `SayAll`、出现多个同名模块、回退到电脑麦克风、音源格式错误。

### 4. 首次按下与首字低延迟

步骤：

1. 在目标输入框聚焦，开始录音或听写。
2. 极快按下并松开遥控器语音键，说一个短字或短词。
3. 重复 5 次，记录目标工具是否出现完整文字。

预期：

- 不等待双击或长按阈值，按下后立即进入收音。
- 每次第一次输入即成功，不出现第二次才成功。
- 日志中同一 generation 的 `first_pcm` 记录可关联，`trigger_down_to_first_pcm_ms` 有实际数值。

失败判定：固定等待、首次会话失败、首字缺失、需要重按第二次。

### 5. 正常短句与尾音完整

步骤：

1. 按住语音键说一句 2 到 5 秒的短句。
2. 松开语音键，不立即再次按键。
3. 等待目标工具输出文字。

预期：

- 最后 1 到 2 个字完整出现。
- 日志同一 `audio_generation` 显示 `completion=normal`、`audio_interrupted_samples=0`、`audio_pending_samples=0`。
- 正常结束路径没有 flush、清空队列或提前截断。

失败判定：尾字缺失、正常路径出现 `completion=forced`、排空未完成就结束会话。

### 6. 快速连续两句

步骤：

1. 第一句松开后，在第一段仍在排空时立即按下第二句。
2. 重复 5 次。

预期：

- 第二句首字不丢，第一句尾音不丢。
- 两个 generation 不混流；旧 generation 的迟到数据被忽略而不是进入新会话。

失败判定：第二句首字缺失、第一句尾音进入第二句、会话生命周期被中断。

### 7. 断连、取消与恢复

步骤：

1. 语音进行中关闭遥控器或移出范围。
2. 重新连接后再次发起语音。
3. 语音进行中退出应用并重启。

预期：

- 进行中的会话只产生一个终态，异常路径记录 `completion=forced`、中断样本数和原因。
- 输入抓取、uinput 按键和虚拟音源在退出后释放。
- 重启后可以建立新会话，不出现卡死或残留按住键。

失败判定：修饰键或 F5 卡住、虚拟音源残留、应用退出后进程仍占用 uinput、恢复后无法再次收音。

### 8. 普通按键映射与按住连发

步骤：

1. 在支持焦点的文本框和列表中逐个按下方向键、确定、返回、主页、菜单、TV 和音量键。
2. 按住方向键、返回和音量键各 2 秒。
3. 关闭映射开关，重新测试同一组按键。

预期：

- 默认动作与页面显示一致。
- 按住只对配置允许的按键连发，松开立即停止。
- 关闭映射后系统原生按键直通，不出现重复注入。

失败判定：按键重复触发、松开后继续连发、开关关闭仍注入、动作与显示不一致。

### 9. 权限不足与恢复

步骤：

1. 临时移除当前用户对 `/dev/uinput` 的写权限，或使用无 `uaccess` 的会话启动应用。
2. 观察映射和语音键状态。
3. 恢复权限并重新登录后启动应用。

预期：

- 权限不足时明确显示“系统直通”，不伪造接管成功。
- 语音键按原生 F5 直通，普通按键不被独占。
- 恢复后可正常抓取和注入。

失败判定：应用崩溃、无提示、权限不足时仍宣称映射就绪、恢复后必须重装才能使用。

### 10. 中文、英文、浅色与深色

步骤：

1. 分别以 `LANG=zh_CN.UTF-8` 和 `LANG=en_US.UTF-8` 启动。
2. 在 GNOME 设置中切换浅色和深色外观。
3. 检查主窗口、状态栏菜单和提示文本。

预期：

- 静态标签、按钮和说明文案在中文与英文下完整，中文最终字号不低于 12pt。
- 无裁切、重叠、不可读对比度或缺失控件。
- 状态栏不可用时主窗口仍可用。
- 蓝牙、音频、权限等实时状态当前可能保持中文；这属于已知本地化缺口，不能据此宣称全英文状态验收通过。

失败判定：静态文案缺失或裁切、中文过小、浅深色不可读、界面依赖状态栏才能操作。

## 稳定功能回归

- 重新登录后只自动启动一个实例。
- 蓝牙连接、断连和重连不破坏现有系统蓝牙设备。
- 虚拟麦克风不改变系统默认输入设备，不替代电脑麦克风。
- 正常语音不丢尾音，异常语音有唯一终态。
- 应用退出后释放 evdev、uinput、FIFO 和 Pulse 模块。

## 日志收集

```bash
tail -n 200 ~/.local/state/sayall-linux/sayall.log
pactl list short sources
pactl list short modules | grep -i sayall || true
ls -l /dev/uinput
```

收集前确认日志不包含用户语音、文字、蓝牙地址、设备身份、路径或第三方 App 私有状态。关键日志应包含同一 `audio_generation` 的 `ATVV STREAM`、`ATVV VOICE phase=first_pcm` 和 `ATVV VOICE phase=completed`。
